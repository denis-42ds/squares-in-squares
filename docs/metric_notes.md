Всё ниже выведено чтением кода, не экспериментом. Пометка **[ЭКСП]** = нужно проверить на Kaggle или локально.

## 1. Формат файла

- Колонки: `id,n,square_id,x,y,angle`. `id` перед скорингом удаляется, но колонка должна быть.
- В sample: `id = n(n-1)/2 + square_id`, 500 500 строк, порядок (n, square_id), 12.87 MB. Сохраняем ту же нумерацию id даже для частичных файлов. **[ЭКСП]** требует ли Kaggle совпадения id с solution.csv (код метрики этого не показывает).
- Для каждого n: ровно n строк; множество `square_id` ровно {0..n-1}; `square_id` парсится `int()` (значит "3", не "3.0").
- `x, y, angle`: после `strip()` должны подходить под `^[+-]?(\d+\.?\d*|\.\d+)([eE][+-]?\d+)?$`, длина <= 100. Не проходят: nan, inf, выражения, hex, `1_0`. Проходят: `.5`, `1.`, `+1e-3`, `0`.
- `|x|,|y| <= 1e4`; `|angle| <= 100` (радианы, до приведения по модулю 2π). (x,y) — центр квадрата.
- Контейнера в файле нет: L измеряется по bbox всех углов (трансляционно-инвариантно). Контейнер осе-параллельный; общий поворот упаковки меняет L.
- Фатально для всего сабмита (ParticipantVisibleError): нет колонок `n,square_id,x,y,angle`; `n` не int; `n` вне [1,1000].
- Нефатально, только этот n получает grid ceiling: неверное число строк, неверные square_id, не парсится число, выход за границы, перекрытие, `L < sqrt(n) - 1e-7`, любое исключение в воркере.
- n, отсутствующие в файле, получают grid ceiling. Строки для n вне solution.csv игнорируются.

## 2. Формулы

- Углы квадрата: `h=0.5; d1=(h*c-h*s, h*s+h*c); d2=(-h*c-h*s, -h*s+h*c)`; углы = `centre ± d1`, `centre ± d2`. Центр относительно квадрата 0.
- `L = max(max_x-min_x, max_y-min_y)` по всем 4n углам, mpmath при 60 знаках из исходных десятичных строк. Никаких допусков в L: считается точно.
- `score(n) = float(L)/sqrt(n) - 1`, затем `max(0, .)`. Итог = сумма по n из solution.csv.
- Grid ceiling: `ceil(sqrt(n))/sqrt(n) - 1`. Невалидный пазл не хуже тривиальной сетки: цена ошибки = потеря выигрыша только по этому n.
- Защита: `float(L) < sqrt(n) - 1e-7` => пазл отклонён. Для n=k² сетка даёт ровно 0, улучшить нельзя.
- Угол в геометрии приводится `% 2π` (float-префильтр); в интервальной проверке используется исходная строка. Симметрия квадрата π/2: нормализация угла в [0, π/2) геометрически эквивалентна.

## 3. Проверка перекрытий (verify_puzzle)

1. Sweep по AABB с pad = 1e-7: пары, чьи AABB не пересекаются, не проверяются (корректно, зазор > 2e-7).
2. Float SAT по 4 осям (оси обоих квадратов), `undecided_tol = 1e-8`:
   - есть ось с overlap < -1e-8 => separated;
   - иначе min overlap > 1e-8 => overlapping => **весь пазл отклонён сразу**;
   - иначе (все оси >= -1e-8, min overlap в [-1e-8, 1e-8]) => undecided.
3. Undecided-пары: интервальная арифметика (mpmath iv) на 50, 100, 200, 500 знаках. Пара сертифицирована, если на какой-то оси верхняя граница overlap <= 0 (`iv_le` True). Если ни одна ось не даёт True и есть неопределённость на максимальной точности => "Overlap undecidable" => пазл отклонён.

Следствия:
- Истинное перекрытие любой величины > 0 не проходит.
- Любой положительный зазор > ~1e-45 (на оси SAT) сертифицируется на 50 знаках; меньшие — на следующих уровнях.
- **Точное касание** проходит только если интервалы вырождены в точку: оба угла ровно `0`, центры точно представимы в двоичном виде (например `0.5`, `1.5`). Касание с недвоичными десятичными (например `0.1` и `1.1`) или с иррациональной геометрией (повёрнутые квадраты) даёт интервал, содержащий 0, и пазл будет отклонён. **[ЭКСП] локально, T2 из скрипта B.**
- Поэтому в упаковках с наклонными квадратами все контакты должны иметь зазор >= δ (см. п. 5). Для чистых сеток на `k+0.5`-центрах и угле `0` зазор 0 допустим (как в sample).

## 5. Рекомендуемый eps для нашего валидатора

- Внутренний допуск: **`SEP_EPS = 1e-12`**, то есть для каждой пары `max over axes (-overlap) >= 1e-12`, кроме пар чистой сетки (оба угла ровно 0, двоичные центры), где допустим 0 с точной проверкой.
- Обоснование снизу: float64 при координатах до ~32 имеет ulp ~3.6e-15; ошибка corner+projection ≲ 1e-14, консервативно 5e-14. 1e-12 даёт запас >= 20x. Меньше 1e-13 знак зазора уже не надёжен.
- Обоснование сверху: цена ≈ δ·L/√n на пазл, для 1000 пазлов ≲ 1e-9 суммарно. Разброс топ-1...топ-20 ~0.15, то есть δ=1e-12 не влияет.
- Достижение зазора: финальный шаг "scale-polish": масштабировать центры от центроида на `λ = 1 + (δ + max_overlap)`. Зазор по оси растёт минимум на `(λ-1)·(проекция Δc >= ~1)`. Прирост L < `(λ-1)·L`.
- Запись: числа через `repr(float)` (<= 17 значащих цифр). Тогда десятичная строка и double совпадают, и неизвестное правило чтения CSV (str или float64) не меняет результат. Угол оси-параллельных квадратов писать строго `0`. Угол нормализовать в [0, π/2).
- Финальный гейт перед записью в best[n]: локальный `evaluate_single_puzzle` из метрики (тот же код, что на Kaggle). Прошёл локально => пройдёт на Kaggle, при условии той же версии метрики и сопоставимой mpmath (в коде явно учтены 1.3 и 1.4). Гейт дорог (интервальные пары), поэтому только для кандидатов, прошедших быстрый float/numba-префильтр с `SEP_EPS`, и только для изменённых n.
